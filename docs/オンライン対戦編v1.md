# オンライン対戦編 設計 v1（リアルタイム・あいことば1対1）

友だちと **あいことば（ルームコード）** で つながって、手持ちアルモンで
**1対1のターン制バトル** をする機能。GitHub Pages（静的配信）は そのままに、
通信だけ 外部の **WebSocket 中継サーバー** に つなぐ。

凡例：★確定 ／ ☆提案（実装時調整可）／ �zumi=済

---

## 0. 方針（決定ずみ）★
- 通信基盤：**WebSocket 中継を 別ホスト**（Render/Railway/Fly、または PartyKit/Cloudflare）。
- マッチング：**あいことば（ルームコード）で 友だちと 1対1**（ランダムなし）。
- 子ども向け安全設計：フリーチャットなし・個人情報なし・コードを知る相手だけ。

## 1. なぜ この形か
- 静的サイト単体では 常時接続を さばけない → 小さな中継サーバーを 1つ足す。
- バトルは **ターン制** なので、アクションゲームのような 厳密な同期は不要。
  「各自の 行動を 毎ターン 交換して 同じ結果を出す」で 遅延に強い。

## 2. 同期モデル ★：ホスト権威（authoritative host）
RNG（乱数：ダメージ幅・急所・命中・捕獲）の ズレを防ぐため、**部屋の1人目
（host）が 唯一の 計算役** になる。
1. host / guest とも 相手の 行動選択（わざ/交代/どうぐ/にげる）を 中継経由で送る。
2. host が 両者の行動＋自分の乱数で **1ターン分を解決**し、結果を
   「イベント列（だれが何をした・ダメージ・状態変化・ひんし…）＋確定した新状態」
   として guest に送る。
3. guest は そのイベント列を **再生するだけ**（自分では 乱数を回さない）。
- 利点：ズレない・実装が明快。欠点：host を信頼する（友だち対戦なので許容）。

## 3. メッセージ（中継の `relay.data` の中身）☆
```
hello    {party:[{dataId,level,moves,gender,nature,...}], name}   // 開幕にチーム提示
ready    {}                                                       // 準備OK
action   {turn, kind:"move"|"switch"|"item"|"run", ...}           // その ターンの行動
resolve  {turn, events:[...], state:{...}}                        // host→guest 解決結果
sync     {state}                                                  // 復帰・ずれ検出用
bye      {reason}                                                 // 退出
```
中継サーバーは 中身を見ず そのまま 相手へ流す（`{t:"relay", data:...}`）。

## 4. チーム・ルール ☆
- 持ち込み：手持ち（タマゴ除く）から 最大3体を選ぶ（フェア＆短時間）。
- レベル：まずは **そのままの レベル**。将来 「Lv50 に そろえる」オプション。
- 勝敗：相手の 出せるアルモンが 全員 ひんし で 決着。どうぐ/にげる の可否は要調整。

## 5. 画面フロー ☆
1. メニュー or 施設「たいせんスペース」から **たいせん** を開く。
2. 「へやを つくる」= コード生成＆表示（host）／「あいことばで はいる」= 入力（guest）。
3. 接続 → おたがいの チーム提示（hello）→ 両者 ready → バトル開始。
4. バトルは 既存 BattleScene を **ネット駆動** に拡張（相手の行動は 中継から）。
5. 切断時：「あいてが きれちゃった」で フィールドへ 復帰（勝敗は無効）。

## 6. 実装フェーズ
- **P0（済 �zumi）**：中継サーバー `netcode/relay`（あいことば・host/guest・転送・
  満室・切断通知）。2クライアントで ローカル検証ずみ。README に デプロイ手順。
- **P1**：ゲーム側 ネットクライアント（接続・再接続・型付きメッセージ）＋
  「たいせん」ロビーUI（へや作成/参加・相手の接続表示・チーム提示・ready）。
  `NEXT_PUBLIC_BATTLE_RELAY_URL` 未設定なら メニュー非表示（本番安全）。
- **P2**：ネット駆動バトル。BattleScene を host権威の ターン交換で 動かす
  （行動送信→host解決→両者で 同じ演出）。切断・投了・タイムアウト処理。
- **P3**：仕上げ（持ち込み選択UI・レベル統一オプション・簡単な 定型スタンプ・
  再戦・安全/不正対策の見直し）。

## 7. yasudaさん が やること（P1 に進む前提）
1. `netcode/relay` を Node ホスト（Render など）にデプロイ、または PartyKit へ。
2. 得られた **`wss://…` の URL** を共有 → ゲームの
   `NEXT_PUBLIC_BATTLE_RELAY_URL` に設定（Pages の ビルド環境変数）。
   - 設定するまで 対戦メニューは 出さない（未完成ボタンを 見せない）。

## 8. 安全・プライバシー ☆
- 知らない人と 当たらない（コードを 教えた相手だけ）。ランダムなし。
- 名前は 表示用の 短い文字列のみ・自由チャットなし（定型スタンプは P3 で検討）。
- 中継は 中身を保存しない・アカウント不要。
